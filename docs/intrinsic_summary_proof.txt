ISA intrinsic 증명과 함수 요약 재사용 — semantics26

목적
기준 bf08469af4b060b6d4f99c409bf44a942297ebe3의 일반 메모리 sink 강화에 이어,
미지원 CALLOTHER 때문에 실제로 증명 가능한 함수 요약이 손실되는 문제를 강화한다.
OW2 함수 주소, 함수 이름, 키코드, vector 이름에 맞춘 통과 예외가 아니다.
동일 ISA 연산을 쓰는 다른 바이너리에도 적용하는 번역 의미 규칙이다.

함수 요약 모델을 쓰면 되는가
된다. 다만 수동 declared model은 외부 계약/명명된 가정을 공급하는 경로이고,
derived summary는 본문에서 증명된 사실을 저장하고 다시 적용하는 경로다.
미지원 userop의 call_clobber_read를 포함한 요약을 저장해도 RSP 증명이 새로 생기지 않는다.
이번 변경은 하위 연산을 먼저 정확히 해석하여 기존 summarize_function과
derive_proven_call_effect가 RSP+8을 도출하고, 그 사실이 저장된 요약에서도 재사용되게 한다.
기존 내부 RVA binding은 derived template를 거부하며, 이를 단순히 해제하지 않았다.
저장된 외부 derived summary 적용의 기존 derived-model-runtime-matches 가정도 그대로 표시한다.

avx2.sinc의 VPCMPEQW constructor는 memory LOAD와 architectural destination 쓰기를
해당 value intrinsic 밖에 둔다. intrinsic은 32바이트 두 값의 16개 word equality 결과다.
Intel SDM253667-060US의 VEX.256 VPCMPEQW 의미와 destination/flags 효과를 감사했다.
https://www.intel.com/content/dam/www/public/us/en/documents/manuals/64-ia-32-architectures-software-developer-vol-2b-manual.pdf
printed pages4-244..4-249, zero-based PDF page248의 VEX.256 연산 설명.
이것은 번역기/ISA 의미에 대한 명시적 신뢰 기반 확장이다. Z3만으로 Intel 하드웨어나
Ghidra 컴파일러 전체의 정당성을 증명했다고 주장하지 않는다.

증명 코드
intrinsic_semantics.py:
  backend 공통 packed-lane lowering, Python 구체 평가와 Z3 검사가 같은 구현을 사용한다.
  독립적인 per-bit ISA reference와 전체256bit 입력의 miter가 UNSAT이다.
  다른 lane의 개입 불변 UNSAT 및 양 입력의 lane 내부 byte 영향 witness SAT를 확인한다.
intrinsic_refinements.py:
  감사된 언어/version/index/name과 constant-index4B, 두32B register/unique 입력,
  32B unique 출력 및 실제 address-space classification이 모두 맞아야 승인한다.
  출력이 있다는 이유나 userop 번호 하나만으로 순수성을 추론하지 않는다.
  미지원 signature는 기존 opaque CALL OTHER로 남긴다.

엔진 연결
normalize.py: 원 CALLOTHER operation과 실제 SSA 입력/출력을 유지한다.
  원 normalized graph의 NodeRecord.semantic_identity에 증명 규칙을 기록한다.
call_clobber.py / function_summary.py / forward.py:
  동일한 승인 intrinsic 집합을 chi/legacy call-clobber, summary crossings와 probe에서 사용한다.
  승인된 value intrinsic만 opaque call crossing에서 제외한다. 원 데이터 연산을 삭제하지 않는다.
  앞선 미지원 호출이 입력을 clobber했다면 그 부채는 그대로 남긴다.
lane_slice.py: 결과 byte9를 요구하면 두 입력의 bytes8..9만 따라간다.
operation_records.py: 원 node에 semantic metadata를 기록하며 동일한 검증 의미로 평가한다.
  metadata 변조, 잘못된 index/폭/형식, 미지원 userop는 평가를 거부한다.
  메모리 LOAD/alias/조건/앞선 call debt는 제거하지 않는다.
