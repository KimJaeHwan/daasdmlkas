Physical memory sink strengthening — 개발 에이전트 인계 기록

목적과 원칙

이 변경은 OW2/SendInput 사례만 통과시키는 패치가 아니다.
일반적인 '포인터가 가리키는 부분 바이트를 함수 호출 전에 소비'하는 질의를 강화한다.
사용자 요구: 증명되어야 하고, 연결은 그래프에 포함되어야 하며, 가정을 최소화한다.
새로운 모델/ABI/종료/메모리 보존 가정을 추가하지 않는다.
후보 출처 라벨이나 오류 메시지 개선을 실제 바이트 연결의 성공으로 취급하지 않는다.

발견한 현상

실제 키 입력 함수에서 SendInput 직전 RDX의 SSA 정의는 찾는다.
그러나 물리 sink [RDX+8, 2 bytes]를 값 정의에 결합하지 못해 unbound root가 된다.
포인터는 entry RSP를 기준으로 offsets=[-464,0]인 symbolic dereference로 표현됐다.
_FunctionPhysicalStateBackend.memory_candidates -> _direct_span은 길이 2 경로를 거부한다.
relational fallback도 동일 폭/동일 affine relation의 단일 지배 STORE를 찾지 못했다.
실제 벡터 쓰기는 16바이트이고, 직접 복사와 재할당 삽입 경로로 나뉜다.
KeyNameToVK 후보 라벨은 스택의 임시 INPUT.wVk STORE와 복사 값에 남지만,
이것이 최종 API 버퍼의 특정 2바이트를 증명한 것은 아니다.

기존 R1a의 '현재 상태를 증명하거나 거부' 원칙을 완화하면
과거 슬롯 값, 미지원 분기, 호출 전 값으로 잘못된 완전 결과를 만들 수 있다.
따라서 조용히 후보를 버리거나, dominance/call/alias 장벽을 제거하는 방식은 사용하지 않는다.

코드별 변경

1. src/tdo_v2/integration/configured_function_pointer_values.py
   complete_physical_pointer_candidates의 LOAD 처리에서 정확히 정착된 local memory read의
   definition을 LOAD 시점에 따라간다. definition_for_span/read_settled가 거부하면 기존
   symbolic dereference를 유지한다. sink 시점의 슬롯을 다시 읽는 재해석은 하지 않는다.
   p=*slot 후 slot이 바뀌더라도 p는 읽을 때의 포인터다.

2. src/tdo_v2/integration/configured_physical_state.py
   - 모든 pointer alternative가 물리 span으로 바뀌어야 exact candidates를 반환한다.
     지원되는 path 하나만 남기고 미지원 path를 버려 falsely unique로 만드는 것을 막는다.
   - value_fragments로 definition ID와 그 정의 자신의 storage에 속한 정확 source_span을 함께 전달한다.
   - relational STORE가 요청보다 넓어도 포함 관계/현재성/주소 관계가 모두 증명되면
     little-endian에서 요청 바이트만 source_span으로 투영한다.
   - 동일 affine root, range containment, source read_settled, dominance,
     keys_between 및 intervening call/overlap 거부는 유지한다.
   - 이전 value_ids adapter는 부분 값에 넓은 ID만 노출하지 않도록 기존 동일 폭 계약을 유지한다.
   - big-endian 부분 투영은 새로 지원한다고 주장하지 않고 보수적으로 거부한다.

3. src/tdo_v2/physical_state.py
   PhysicalValueFragment와 PhysicalStoreReceipt를 추가한다.
   receipt는 실제 STORE/consumer operation, source byte span, target affine root/offset,
   폭, 위치와 검사한 사이 연산을 보존한다. source span과 target memory span을 혼용하지 않는다.

4. src/tdo_v2/integration/configured_boundary_demands.py
   부분 바이트 receipt를 physical_spans에 전달한다.
   같은 넓은 definition을 가리키는 서로 다른 selector의 disjoint bytes를 보존한다.
   canonicalization은 동일 node의 span을 합치고 서로 다른 소비 occurrence를 유지한다.
   겹치는 동일 source 요구를 중복 결합하지 않는다.

5. src/tdo_v2/observed_boundary_projection.py
   경계 node에 typed binding_receipts를 보관한다.

6. src/tdo_v2/integration/configured_physical_binding_graph.py (새 파일)
   검증된 binder receipt에서만 query proof graph를 만든다.
   원 normalized SSA의 source/STORE/consumer node ID를 참조한다.
   stored_value_bytes -> current_memory_bytes -> physical_consumption의 연결을 기록한다.
   원 normalized graph를 바꾸거나 미해결 부채를 해제하지 않는다.
   candidate_only=False는 해당 local binding edge가 증명됐다는 뜻이다.
   상위 모든 origin 및 프로그램 전체의 완전성을 뜻하지 않는다.

7. src/tdo_v2/summary_engine.py 및 engine.py
   RootSlice.explanation에 physical_binding_graph를 노출한다.
   summary operation record에도 동일 proof graph를 포함한다.
   legacy는 기존 include_explanations 옵션을 존중한다.
   summary의 byte-lane source 선택과 legacy의 node-level 보수적 origin 집합은 구분한다.
   포함 범위: 결과의 명시적 query proof graph이며 원 immutable normalized dependencies에
   새 edge를 삽입한 것은 아니다. 원 그래프만 순회하는 기존 소비자는 이 별도 필드를 읽어야 한다.
   결론 계산은 검증된 source_span을 seed로 기존 lane graph를 따라간다.

8. src/tdo_v2/summary_templates.py, models/derived, tests/intra/template_fingerprint.json
   의미 버전을 25로 올리고 이전 의미의 파생/캐시 재사용을 차단한다.
   파생 모델은 버전 숫자만 바꾼 것이 아니라 원 DLL Bundle에서 실제 재도출한다.

실제 사례와 지원 범위의 경계

이 변경만으로 임의 std::vector 재할당/루프/간접 callback/예외 효과를 증명한다고 주장하지 않는다.
분석 범위에 helper 본문을 넣은 것과 호출 지점에 effect를 증명해 붙인 것은 다르다.
실제 최종 INPUT[]에서는 reserve/push helper의 미해결 terminal/tail 경로,
begin/end 관계와 가능한 재할당의 별도 증명이 필요할 수 있다.
증명되지 않은 최종 wVk는 unbound/incomplete로 남겨야 한다.
OW2 주소, SendInput, wVk, 벡터 이름에 맞춘 엔진 조건은 없다.

검증된 수정 전후 차이

동일 무가정 synthetic 재현에서 기준 semantics24는 complete=False, origin labels=[]이며,
수정 semantics25는 complete=True, origin labels=[hi.ret]이다.
요청은 16바이트 STORE의 +8 위치 2바이트이며, 다른 절반 lo.ret는 summary 결과에 섞이지 않는다.
결과와 operation record 양쪽의 physical_binding_graph가 동일함도 확인했다.
legacy는 node 단위의 보수적 출처 집합을 유지하되 hi.ret 및 정확한 2바이트 receipt가 남는다.
이 결과는 실제 OW2의 성공 증거와 구분한다.

통합 시 주의

1. 이 브랜치는 54fd317 기반이다. 실시간 main이 진행 중이면 최신 동작을 읽고 충돌을 검토한다.
2. R1a 장벽과 새 freshness/byte receipts를 함께 유지한다. 안전 검사를 지워 충돌을 해소하지 않는다.
3. semantics25가 이미 다른 의미에 사용됐다면 통합 브랜치의 다음 의미 버전을 선택하고
   파생 모델/지문을 다시 실제 재생성한다. 버전 번호만 일괄 치환하지 않는다.
4. 새 graph 필드는 설명용 증명 그래프이며 후보 source를 exact graph edge로 승격하지 않는다.
5. 구체적 관찰/지원 범위를 전체 프로그램 완전성으로 바꾸어 보고하지 않는다.
